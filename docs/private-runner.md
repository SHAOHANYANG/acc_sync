# 受控自动分析入口

本说明落实用户 2026-10-29 指定的仓库规则。AI 可以运行 `run_real.py` 并解释它输出的白名单聚合数字；不能读取输入行、详细结果表或真实图。它不是对学校政策范围的额外认证，也不是操作系统沙箱。

## 唯一工作方式

```powershell
python generate_fake_data.py
python run_fake_tests.py
python run_real.py --fake
python run_real.py --check
python run_real.py
```

前3步只用虚构数据。测试成功会生成与当前源码、测试、规则和配置相绑定的凭据；真实检查和计算要求凭据仍有效。修改代码或配置后重新运行假数据测试。旧 `sync_eval` CLI 只用于开发假数据，不再用于真实输入；常用旧读取函数会拒绝从 data/ 直接读取。

没有通过检查就停止，不尝试其他文件路径、压缩包、密码、临床文字或旧私有目录。`check_data.py` 由入口自动调用，不能单独运行来查看真实数据。

## 一次性放置输入：由数据持有人完成

AI 不搜索原文件，也不迁移旧 `local-data/`、`private/`、原始手表或临床资料。请数据持有人在本地按下列契约放置已准备好的副本，无需向聊天发送内容。

```text
data/
  energy/session_01.csv
  annotations/synchrony/session_01.csv       可选：独立人工同步区间
  annotations/non_synchrony/session_01.csv   可选：明确人工非同步区间
  annotations/uncertain/session_01.csv       可选：不确定区间
  predictions/session_01.csv                可选：Emily 等方法的预测事件
```

目录名称是固定代码标签，不是临床文字。每个文件名必须为 `session_` 加至少两位数字再加 `.csv`；不在文件名中附加日期、姓名或备注。不支持自由文件名、额外目录、压缩文件、加密文件、Parquet、Excel、HTML 或 JSON 输入。符号链接和 Windows junction 会拒绝，不跟随链接读取。

能量文件必须恰好两列：

```csv
time_s,energy
```

其余文件必须恰好两列：

```csv
start,end
```

时间使用同一参照下的非负秒数，也接受表示时长的 MM:SS / HH:MM:SS。不要放入原始日期时间；程序不擅自完成绝对时钟或录像对齐。能量为非负有限线性数值，空值和 NaN 保留为缺失；无穷值、负数或任何文字值会被拒绝。能量时间必须严格递增，事件 end 必须大于 start。

表头也采用封闭名单，因此“名字恰好被放在列名里但下面都是数字”的文件仍会被拒绝。附加的文字列不允许。原始数值中的极端值不会被随意删除。

annotations/ 下不同类别的时间区间不得重叠；未标注不能自动视为非同步。独立性、共同时间参照和完整标注情况由数据持有人确认后，在 real_config.json 中设置；AI 不得为了获得指标自行把确认开关改为 true。

## 校验与错误输出

不合格输入只显示类似：

```text
CHECK_FAILED: 第1个文件，第2列不合格
```

文件序号按固定目录/文件排序的检查顺序计算。第0列表示文件名、文件类型、目录、编码或整体格式问题；第0个文件表示没有可接受的数据根目录或没有输入文件。不会打印文件名、列名、行号、内容或异常原文。

分析出错只显示受控类型和公开源码位置，例如：

```text
ERROR type=ValueError file=safe_pipeline/analysis.py line=123 function=analyse
```

这里只示意格式，行号以实际公开源码为准。异常类型、仓库文件名和函数名也经过白名单检查；自定义异常名若含输入信息，会降为 RuntimeError。没有 traceback、异常正文、源代码行、局部变量、输入路径或日志。

## 输出边界

分析运行在独立子进程，stdout 和 stderr 在启动时都连接到系统空设备，不保留原始输出文件。print、sys.__stdout__、原生 os.write、继承标准输出的子进程、warnings 和异常 traceback 均不能直接传给聊天；文件日志处理器也被替换为丢弃处理器。

子进程仅返回结构化结果。父进程再次检查封闭字段集合、数据类型和有限数值，然后输出最多3位有效数字。文字字段、额外字段、NaN/Inf 均不能混入汇总。NA 表示当前不能计算，不是0。

成功输出分为固定四类：

| 类别 | 允许的内容 |
|---|---|
| SUCCESS | session数、文件数、参数运行数、完成独立比较及评估的session数 |
| RULES | 规则编号、窗宽、规则类型编码、阈值/分位数、持续时间、参与session数、候选总数和总秒数 |
| COMPARISONS | 窗宽、session数、两组窗口数、同步减非同步的平均能量差、描述性 r_pb |
| EVALUATIONS | 来源编码、规则编号、窗宽、session数、Hit/Miss、未匹配预测数，以及具备完整参考覆盖时的误报/precision/recall |

method=1 为单阈值＋时长，method=2 为高短 OR 较低长两分支。评估 source=0 是基线规则，source=1 是 predictions/ 中的外部分段；后者不是重新按能量生成的标签。对外部分段 width_s=0 表示其本身没有被窗口化。

多个session合并显示时，候选数量/时间求和，low_threshold/high_threshold 为各session对应阈值的平均，分位数配置保持可辨认。比较按同一窗宽汇总已纳入的窗口，r_pb 仅描述，不作独立样本 p 值推断。不同session的阈值平均不代表统一适用阈值。

```powershell
python run_real.py --last-summary
```

此命令只重新输出已保存并再次通过结构检查的安全汇总，不重新分析输入，也不打开详细表或图。

## 研究分析如何复用

- 复用现有 `sync_eval.exploration.explore`：2s/4s 均值、阈值/持续时间扫描、单规则、两分支规则和候选合并。
- 复用 `compare_reference`：独立时间戳类别比较，不从能量阈值造标签；跨类别、不确定、未完整标注窗口排除并计数。
- 复用 `evaluate_events`：事件一对一 IoU 匹配、Hit/Miss、缺失覆盖处理；没有独立性和对齐确认时跳过。
- 有 annotations_complete 确认仍不够：还需明确正/负时间区间实际覆盖全部有效时间，才允许把未匹配预测记作误报。
- 不声明高能量等于真实同步；不把 r_pb 或候选数量解释为准确率。
- 参考上游5.12秒分析窗、时间标记和能量尺度的既有局限继续适用，本入口不偷偷修改它们。

## 保存位置

```text
results/tables/run_.../        详细研究结果与参数，仅用户查看
results/figures/run_.../       真实图（含HTML），仅用户查看，AI禁止打开
results/_control/             测试凭据、受控汇总、瞬时结构化通信
fake_results/                 完全虚构的测试运行输出
```

每次使用新的运行目录，不覆盖原始数据。主程序不会启动浏览器、预览图片或把真实输出上传；AI 不通过别的命令读取这些详细文件。瞬时通信文件运行后删除，不保存原始日志。

`explore` 原有报告描述它自己是否执行标签比较；封装入口另外完成的比较/评估以 `_controlled_analysis.json` 和 run_summary.json 为准，避免把原函数未接收标注误读为整个封装没有比较。

## 假数据和回归测试

`fake_data/valid/` 与 data/ 内部结构相同，使用 session_90、session_91。真实能量范围不由这些虚构数字决定。`fake_data/adversarial/` 为故意不合格的输入案例，含标记 ZZTEST_Qx7；有效假能量也含 7777.7777，以确认处理数值后不会原样回显。

测试覆盖整表打印、原生标准输出/错误、子进程、warnings、文件日志、自定义异常、含数据值异常、文字污染汇总、非有限数值、恶意参数、表头/文件名/列值错误、缺失保留、冲突标注、凭据失效、旧入口拦截及受控汇总重新检查。测试的 mock data/ 位于全新临时假工作区，不读取项目真实 data/。

此机制防止正常程序和测试覆盖的意外输出进入模型，不能约束拥有任意文件权限的恶意程序主动绕过入口、建立新输出通道或访问网络。AGENTS.md 是持续操作规则，不是操作系统权限隔离。若需要更强边界，应另外配置权限隔离，不把本入口称为完全匿名或不可绕过。

子进程同时拦截常见浏览器打开接口和 Python socket 连接/监听/域名解析，避免意外预览或联网；这仍不等于操作系统级网络封锁。

data/ 和 results/ 均被忽略，旧 data/ 跟踪项从当前分支移除。Git 忽略不会清除已有历史；本次不重写历史，不修改上游。
